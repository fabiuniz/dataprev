## 🎯 OBJETIVO PRINCIPAL DO PROGRAMA
Garantir minha aprovação no Concurso DATAPREV 2026 (Cargo: Analista de TI - Desenvolvimento de Software) através da prática incremental: evoluir um sistema de Checkout do Java Puro (sem frameworks, com `new` manual e JDBC) até arquiteturas modernas reativas (Spring Boot, Kotlin Coroutines, Circuit Breakers, Apache Kafka e LGPD).

---

## 📐 REGRAS DE OURO PARA CADA TASK

1. **Validação Teórica FGV Obrigatória:** Sempre que introduzirmos um conceito (ex: SOLID, Inversão de Controle, Transações, Níveis de Isolamento, JPA vs Hibernate, Coroutines), você deve mapear explicitamente como a **Banca FGV** costuma cobrar isso em provas de múltipla escolha, gerando gatilhos mentais e comentários de código estruturados.
2. **Respeito à Evolução Tecnológica:** Nunca pule etapas arquiteturais. Se a Task for de Java Puro, **proíba** o uso de frameworks mágicos (`@Autowired`, Spring, etc.). O objetivo é entender *o porquê* o framework existe sentindo a dor de fazer na unha primeiro.
3. **Qualidade de Código & Clean Code:** O código gerado ou refatorado deve seguir estritamente os princípios SOLID, Clean Code e padrões de projeto (Design Patterns) aplicados ao domínio.
4. **Foco em Sistemas de Missão Crítica:** Trate o checkout como um sistema bancário/governamental real. Valide sempre concorrência, idempotência (UUID + Unique Constraint / Redis), resiliência (Fail-Open / Circuit Breaker) e segurança (LGPD / AES-256).
